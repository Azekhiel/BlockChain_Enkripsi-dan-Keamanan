## 📝 Prompt Terpadu: Backend Go "Moli-Milo" (5-Lapis Keamanan)

Buat Backend API di Go yang mengimplementasikan arsitektur keamanan *hybrid* berdasarkan Geth PoA (`networkID 1337`) dan Smart Contract `AuditableRBAC` Anda.

### I. Koneksi & Infrastruktur

1.  **Module Go:** Gunakan nama *module* `MoliMiloBackend`.
2.  **Klien Geth:** Hubungkan ke node Geth di `http://localhost:8545` menggunakan `ethclient`.
3.  **Binding Kontrak:** Gunakan `abigen` untuk membuat *Go binding* (`AuditableRBAC.go`) dan buat *instance* kontrak di alamat `0xd4766aFBe333DB354C61628f9229f63f45c12C26` (simpan di `config/constants.go`).

### II. Middleware Keamanan (5 Verifikasi Wajib)

Terapkan *middleware* otorisasi (`auth.go`) yang harus dilewati **sebelum** *handler* API manapun. Middleware harus menjalankan 5 verifikasi ini:

1.  **Verifikasi #1 & #2 (Autentikasi & Anti-Replay):** Asumsikan telah dilakukan oleh *pre-middleware* atau *sign-in handler* yang menggunakan `ecrecover` (Tanda Tangan Digital) dan Nonce untuk memverifikasi alamat user (`userAddress`).
2.  **Verifikasi #3 (Role):** Panggil fungsi *view* `contract.hasRole(userAddress, requiredRoleHash)` di Geth.
3.  **Verifikasi #4 (Policy/Jam Kerja):** Lakukan pengecekan **di sisi *server* Go** (bukan di *smart contract*) untuk memverifikasi jam akses:
    * **Admin:** Selalu diizinkan (24/7).
    * **Finance:** Diizinkan hanya antara jam **08:00 WIB** hingga **20:00 WIB**.
    * **Karyawan:** Diizinkan hanya antara jam **08:00 WIB** hingga **17:00 WIB**.
4.  **Verifikasi #5 (Budget):** Panggil fungsi *view* `contract.checkBudget(requiredRoleHash)` di Geth. Jika kuota habis, kembalikan status `429 Too Many Requests`.

### III. Logika Bisnis & Fitur Admin

Setelah 5 verifikasi lolos, *handler* API harus mengimplementasikan logika berikut:

1.  **Logging Asinkron:** Setelah setiap *request* sukses, *backend* harus mengirim transaksi **asinkron** (menggunakan *goroutine*) ke Geth untuk memanggil `contract.logAccessAndDecrement(userAddress, userRole)`.
2.  **Endpoint Admin:** Buat *endpoint* yang menggunakan *middleware* `ADMIN_ROLE` (`/v1/admin/*`). *Handler* ini harus bisa:
    * Mengakses data sistem yang sensitif (simulasi *audit logs*, dll.).
    * **Mengirim transaksi *tulis* (write transaction)** ke Geth untuk memanggil `contract.setRoleBudget(role, budget)` melalui API (`POST /v1/admin/budget`).

3.  **Endpoint Role-Specific:** Buat *endpoint* untuk masing-masing *role* yang mengembalikan data yang difilter:
    * `/v1/finance/laporan` (Membutuhkan `FINANCE_ROLE`).
    * `/v1/karyawan/data` (Membutuhkan `KARYAWAN_ROLE`).

### IV. Struktur File Go

Implementasikan logika di atas ke dalam struktur file yang telah disepakati:

| File | Fungsi |
| :--- | :--- |
| `main.go` | Inisialisasi dan Router Setup. |
| `config/constants.go` | Konfigurasi Blockchain dan Role Hashes. |
| `blockchain/client.go` | Geth Connection dan Contract Instance. |
| `blockchain/helpers.go` | **Logika Policy Jam** dan *Helper* Blockchain (`CheckBudget`, `LogAccessAsync`). |
| `middleware/auth.go` | Implementasi Middleware 5 Verifikasi Wajib. |
| `handlers/api.go` | Logika Bisnis untuk semua *endpoint* Admin, Finance, dan Karyawan. |
